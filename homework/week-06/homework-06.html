Question 1: KNN and logistic regression

I used seed 432 and a random 70/30 split: 398 training cases and 171 test cases. The same split is used throughout. Means and standard deviations are calculated from the training data only. The positive class is malignant (y = 1).

import numpy as np
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import KNeighborsClassifier
from sklearn.metrics import roc_curve, roc_auc_score

data = np.loadtxt("data/breast-cancer.csv", delimiter=",", skiprows=1)
X, y = data[:, :3], data[:, 3].astype(int)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=432)
scaler = StandardScaler().fit(X_train)
X_train = scaler.transform(X_train)
X_test = scaler.transform(X_test)

# C = infinity removes the penalty; the intercept is fitted.
models = {"Logistic": LogisticRegression(C=np.inf, max_iter=2000, tol=1e-10)}
for k in [5, 15, 25, 35, 45]:
    models[f"KNN k={k}"] = KNeighborsClassifier(
        n_neighbors=k, weights="uniform", metric="euclidean")

q1_rows = []
fig, ax = plt.subplots(figsize=(6, 4.5))
styles = ["-", "--", ":", "-.", "--", ":"]
for (name, model), style in zip(models.items(), styles):
    model.fit(X_train, y_train)
    prob = model.predict_proba(X_test)[:, 1]
    auc = roc_auc_score(y_test, prob)
    q1_rows.append([name, auc])
    fpr, tpr, _ = roc_curve(y_test, prob)
    ax.plot(fpr, tpr, linestyle=style, label=name)
ax.plot([0, 1], [0, 1], "k:", linewidth=0.7)
ax.set(xlabel="False positive rate", ylabel="True positive rate",
       title="Test ROC curves", xlim=(0, 1), ylim=(0, 1.02))
ax.legend(fontsize=8, loc="lower right")
fig.tight_layout()

I prefer Logistic for this split because it has the largest test AUC (0.9822). AUC compares ranking across cutoffs; it does not pick a cutoff. This is a comparison on one test split, so I would use cross-validation for tuning and a fresh test set for a final performance estimate.

At k = 1, the training AUC is 1.0000, while the test AUC is 0.8962. Each training observation is its own nearest neighbor, so its fitted probability equals its label. That perfect training fit does not carry over to new observations.

Larger k averages more neighbors and makes the predictions less sensitive to individual observations. Training AUC generally falls and the gap becomes smaller, although the test results need not change monotonically. Very large k can smooth away useful local differences. Training predictions reuse the fitted data, so test performance is the more useful check here.

Question 3: Peer evaluation of Homework 5

I reviewed Urva-Vashi, Homework 5, Question 2(a). I noticed one setting in the KNN code that could be changed.

Reviewed report

The current call is:

knn_fit = kknn(
    y ~ .,
    train = knn_train,
    test = knn_test,
    k = 5,
    kernel = "rectangular"
  )

The rectangular kernel correctly gives equal neighbor weights. However, kknn() uses scale = TRUE by default, while the question asks for Euclidean distance on the original covariate scale. Having population variance one does not mean the sample standard deviations are exactly the same. Rescaling can therefore change the nearest neighbors and the resulting MSE.

I would add scale = FALSE and make the Euclidean distance setting explicit:

knn_fit = kknn(
  y ~ ., train = knn_train, test = knn_test,
  k = 5, distance = 2, kernel = "rectangular", scale = FALSE
)

  3. Check whether the comparison with lasso in part (b) still holds, and adjust the explanation if needed.

This change does not necessarily improve the MSE; it makes the fitted model match the question.
